# Mobbin 리뷰: 디자인 개선점

2026-10-11. Mobbin에서 교통 앱과 실시간 상태 앱을 살펴보고, 버스어딨니에 적용할 개선점을 정리한 문서입니다. 용어는 [`GLOSSARY.md`](../../GLOSSARY.md)를 따릅니다.

> Mobbin에는 한국 교통 앱(카카오맵, 네이버맵)이 없습니다. 그래서 Transit, Citymapper, Google Maps, Apple Maps와 배달 추적 앱을 레퍼런스로 삼았습니다.

## 전제

- **사용 순간**: 두 가지입니다. 하나는 나가기 전에 집이나 사무실에서 확인하는 경우, 다른 하나는 정류장에 서서 확인하는 경우입니다.
- **범위**: 화면 표현과 상호작용만 다룹니다. 앱 안에서 즐겨찾기를 편집하는 기능은 이번 범위에서 뺍니다.
- **플랫폼**: 웹/PWA를 유지합니다. 네이티브 전용 패턴은 참고만 합니다.
- **디자인 시스템**: shadcn/ui를 기반으로 두고, 큰 숫자 타이포와 노선 색 배지로 시각적 개성을 더합니다.
- **화면 구조**: 묶음 하나가 정류장 하나입니다. 헤더는 `별칭 · 정식 정류장명` 형식입니다 (예: **판교역** · 판교역동편).

## 프로토타입 외 바로 적용

- **PWA manifest**: 홈 화면에 추가할 수 있게 합니다. 홈 화면 위젯의 웹 대안입니다.
- **시간대별 정류장 순서** ([Citymapper Commute](https://mobbin.com/screens/ac91e4d8-25ee-4661-bf9d-15ba587f14ac)): 정류장마다 우선 시간대를 두고, 그 시간에는 맨 위에 표시합니다. 보는 도중에 카드가 움직이지 않도록, 앱을 열거나 다시 돌아올 때만 순서를 바꿉니다. 시간대 표시는 따로 하지 않습니다.

## 보류

- **출발 판단 ("지금 나가면 탈 수 있나")**: 정류장별 도보 시간이 필요합니다. 출발지가 집인지 사무실인지에 따라 값이 달라지는 문제도 있습니다. 출발 상황(장면)마다 도보 시간이 달라 값 하나로 표현할 수 없어서 보류합니다.
- **방면 표시**: 사용자가 이미 어디로 가는 버스인지 알고 있어서 불필요합니다.
- **앱 안에서 즐겨찾기 검색과 추가, 편집 모드** ([Apple Maps](https://mobbin.com/flows/9c98868a-6530-495a-99db-76cc7ce1dda1), [OKX](https://mobbin.com/screens/a63d98cb-a0ca-4bca-82bd-d4c890f3c332)): 정류장·노선 검색 API와 저장소 설계가 필요합니다.
- **포그라운드 도착 알림**: Notification API로 구현할 수 있습니다.

## 불가 또는 참고만

- **혼잡도 / 잔여석**: 현재 API 응답에 해당 필드가 없습니다.
- **지도 위의 실제 차량 위치**: 좌표 데이터가 없습니다.
- **홈 화면 위젯, Live Activity**: 네이티브 앱에서만 가능합니다. 백그라운드 푸시는 PWA 설치와 푸시 서버가 있어야 합니다.

## 프로토타입 계획

- **경로**: `/proto` 경로에 둡니다. 버리는 코드입니다.
- **데이터**: 가짜 데이터 시나리오 전환기를 둡니다. 시나리오는 곧 도착, 도착 예정 없음, 조회 실패, 오래된 데이터, 10정거장 초과입니다. 실제 API로 보는 토글도 함께 둡니다.
- **변형안**: 행 레이아웃만 변형안 3개를 탭으로 비교합니다.
  1. Citymapper식: 큰 숫자 + "다음 N분"
  2. Transit식: 노선 색 배지 + 도착 시간 타일
  3. 진행 바 강조형
- **나머지 항목**: 신선도 표시, 당겨서 새로고침, 오류·빈 상태는 각각 하나의 안으로 만듭니다.
- **테스트 환경**: iPhone Safari와 홈 화면 PWA에서 확인합니다. 같은 네트워크(LAN)에서 `next dev`로 실기기에 띄워, 당겨서 새로고침이 Safari 기본 바운스와 충돌하는지 봅니다.

## 프로토타입 결과

2026-10-11. 변형안 3개(A 리스트, B 타일, C 트랙)를 같은 데이터와 시나리오로 비교했습니다. 프로토타입 코드를 담았던 `prototype/mobbin-redesign` 브랜치(마지막 커밋 `60a8ac1`)는 결정이 끝난 뒤 삭제했습니다.

- **채택: C 트랙.** 노선마다 가로 트랙을 두고, 도착 예정 차량 두 대가 내 정류장(오른쪽 끝)으로 다가오게 표시합니다. 남은 분은 각 차량 위에 붙입니다.
- **제외: C의 "가장 먼저 오는 버스" 요약 카드.** 불필요하다고 판단했습니다.
- **공통 요소는 그대로 채택**: 신선도 표시, 당겨서 새로고침, 실패 시 마지막 값 유지, 빈 상태, 노선 색 배지.
- **노선 유형 기록 방식**: 즐겨찾기에 직접 적기 위해 `favorites.json`을 정류장 단위 구조로 바꿨습니다. 정류장 묶음마다 `alias`, `stopName`, `routes`가 들어갑니다.
